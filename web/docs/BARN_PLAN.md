# 축사 모델 (2D 평면)

농장 허브 **모델** 탭. 위성 위에 부지 구획을 고르고, 그 안에 축사를 놓는 **2D 정본**.

옛 3D 탭은 은퇴. [`BARN_MODEL.md`](./BARN_MODEL.md)

구현: `src/lib/farm/barn-plan-boundary.ts`, `src/components/farm/farm-plan-view.tsx`, `farm-plan-site-map.tsx`  
URL: [`farm-hub-url.md`](./farm-hub-url.md) (`view=model`, 옛 `view=plan`은 같은 탭)

필드 탭은 운영 LIVE 카드 그대로. 위성 부지는 **모델만**.

| 환경 | 기본 |
|------|------|
| 로컬 · Preview · Production | **노출** |

## 흐름 (Fincabout 기준)

허브에는 농장이 이미 있으므로 프로젝트 생성은 생략한다.

| 단계 | 내용 | 상태 |
|------|------|------|
| 1 | 프로젝트 생성 | 생략 |
| 2 | 지도 선택(위성/지도) + 구역 스캔(점 → 경계, 면적) | **구현** |
| 2b | 고른 구획 → 1m 격자 필드 | **구현** |
| 3 | 새 건물 → 독 옆에서 방·각도 맞추기 → 배치 | **구현** |
| 3b | 배치 완료 → 구획 숨김 → **축사 연결** / **컨트롤러 연결** · 우측 **축사 해제** / **컨트롤러 해제**(일괄) · **모델 생성** | **구현** |
| 4 | 회전 | 이후 |

가져올 것: 부지 격자/경계가 캔버스, 고른 뒤 맵 클릭, 2D 정본.  
가져오지 말 것: Farm/Design 카드, 작물 라이브러리, Cattle Ranch 템플릿, 초록 다크 테마, 벽 CAD, AI 주택 생성.

## 2단계 — 위성 + 구역 스캔

전폭 지도. 높이는 헤더·탭을 뺀 `100dvh` 계산(명시 px/vh). 스크롤 `main`의 `flex-1`만으로는 맵이 접힌다.

`KAKAO_JS_KEY`(또는 `NEXT_PUBLIC_KAKAO_JS_KEY`)가 있으면 **카카오맵** (위성=하이브리드, 지도=로드맵, 지적편집도 오버레이). 없거나 SDK 실패 시 Leaflet (SAT=Esri, MAP=OSM 한국). 카카오 JS 도메인: `http://localhost:3000`, `https://smart.autofankorea.com`.

- 확대 후 **구획을 눌러 선택**. **선택 해제**로 고른 구획을 비움
- 면적은 구면 근사(m² / ha). 맵 수치 토큰(`--density-map-value*`)
- 농장 주소 → 좌표: 카카오 도로명 검색이 필지. 실패하면 시·면 중심을 필지로 쓰지 않음. 키: `KAKAO_REST_API_KEY` (`.env.example` 이름만)
- 주소 경계: 확대 후 **구획을 눌러 선택**. **필드로 만들기** → 1m 격자만 남고 지번·지목은 표시하지 않음. 키: `VWORLD_API_KEY`. 브이월드 서비스 URL은 `https://smart.autofankorea.com`(로컬은 `http://localhost:3000`). 조회는 등록분·사이트·운영·로컬 순. 선택: `VWORLD_DOMAIN`. Production 함수 리전은 서울(`icn1`, `web/vercel.json`). 저장본은 다시 열면 선택 복원
- **필드로 만들기** 이후: 고른 구획 안에 위성 타일을 반투명으로 올린다. 브라우저가 `GET /api/farm-plan/sat-overlay?z=&x=&y=`로 JPEG를 받고, 구획 폴리곤으로 자른다. 키: `VWORLD_API_KEY`(WMTS Satellite, 실패 시 Esri 타일). 좌측 상단 **새 건물**을 누르면 임시 동이 올라가고, **독 오른쪽**에서 방·복도를 맞추며 **오른쪽 각도 핸들**로 5° 단위 회전한다. **위·아래 변**은 열식(1–5열), **좌·우 변**은 칸 수. **배치하기**로 확정. 단계 이동(지도 → 배치 → 연결 → 생성)은 도면 **상단 흐름**에서 한다. 격자 위에 단계 버튼을 두지 않는다. 조건이 되면 순서를 건너뛰고 바로 들어갈 수 있다. 지도 레이어는 유지하고, 지도로 돌아올 때만 크기를 다시 잡는다. 지도에서 다른 단계로 들어가면 해당 단계 기하를 맞춘 뒤 교차 페이드한다. 필드 안에서는 배치↔연결↔생성 모션만 돌린다(`--motion-duration-emphasis`). 동이 하나 이상이면 상단 **연결**로 부여 단계. 저장: `sungil.barn-plan.site.v1:${farmId}` (로컬만). 단계는 `sungil.barn-plan.phase.v1:${farmId}`.
- **배치 완료** 이후: 위성·구획 윤곽은 끄고, 동은 **세로로 세운 뒤 가로로 나란히** 모인다(`--motion-duration-emphasis`). 배치 좌표는 유지. 좌측 **축사 연결**로 칸을 묶어 LIVE 축사(유형명+번호)를 붙인다. **컨트롤러 연결**은 윈도우에 들어온 방만 고르고, 그 동에 붙은 축사의 컨트롤러를 그 방에 붙인다. 컨트롤러가 맡은 방은 맞닿은 구간끼리 다른 식별색(채널·알람·브랜드와 겹치지 않는 4~6색)으로 갈리고, 라벨에 방 수가 붙는다. **모델 생성**은 같은 emphasis 모션으로 복도·식별색을 걷는다. 방 격자는 연결에서 붙인 자리 그대로 두고, 컨트롤러끼리 한 덩어리로 다시 붙이지 않는다. 같은 컨트롤러 방은 붙고, 컨트롤러가 다르면(그룹2) 옆은 복도 너비, 위아래는 태그 높이만큼 띄운다. 한 동 안에서 아래 그룹2가 더 좁으면 가로 **중앙**에 맞춘다. 동과 동 사이(그룹1)는 **가장 작은 동**의 짧은 변 100%를 모든 틈에 같이 쓴다. 생성에서는 먼저 각 동의 패킹 크기(구획 여유율+이름 태그)로 가로 자리를 잡고, 방 간격은 그 동 안에서만 벌린다. 그래서 옆 동과 구획이 겹치지 않는다. 휠·핀치로 줌(최소=배경 맞춤, 최대=3배). **연결→생성** 첫 줌은 이름 태그가 생략되지 않는 배율(구획 폭 대비 글자 너비, 상한 3배)이고, 줌인 뒤에는 드래그로 옮긴다. 이름 태그는 배치·연결에서는 구획 **안쪽 중앙**, 생성에서는 각 구획 **바로 위 바깥**(태그 아래변이 구획 상단)에 둔다. 태그 너비는 그 구획 폭을 넘지 않는다. 위아래 컨트롤러 사이 간격은 최소 줌에서 잰 실제 태그 높이(120%)와 복도 중 큰 값에, 위 구획과 1m 틈을 더한다. 위는 축사유형, 아래는 축사번호·컨트롤러 번호만 두고, 번호는 필드 카드와 같이 창고/장치 아이콘+숫자다. 온습도 숫자와 방 수는 태그에 넣지 않는다. 생성에서 방 테두리는 희게 두고, 칸 **안쪽**은 컨트롤러 온·습 판정이다. 둘 다 띠 안이면 에메랄드. 경고·위험이면 온도(온도계)·습도(물방울) 아이콘은 그 컨트롤러 태그에만 두고, 칸 안은 색만 칠한다. 둘 다 이탈이면 칸을 좌(온도)·우(습도)로 나눈다. 우측 상단 **알람 | 권장**으로 판정 띠를 고른다(기본 알람, `sungil.barn-plan.env-band.v1:${farmId}`). 알람=사용자가 정한 상하한(히트맵과 같이 띠 안 가장자리=주의, 띠 밖=위험. 농장·유형·컨트롤러 덮어씀, 기본 10–35℃ · 30–90%). 권장=유형별 생육 표(이탈=주의, 안전망=위험)이며 델린 안내와 같다. 같은 구획의 칸은 같은 표시. 윈도우를 끄는 동안과 연결 카드에 고른 방 수가 보인다. 오른쪽 **축사 해제**는 모든 동의 축사(그에 붙은 컨트롤러 포함)를, **컨트롤러 해제**는 컨트롤러만 한 번에 뗀다. 가로 칸은 환기에서 나누지 않는다. **한 LIVE는 한 동만.** 형태를 고치려면 **건물 다시 배치**. 옛 3D v2 키와는 섞지 않는다.
- 저장: `sungil.barn-plan.site.v2:${farmId}` (부지 경계, 로컬만). v1 건물과 별개
- URL `planBldg` / `planSp` / `planStall` 은 배치 후 포커스용. 지금은 쓰지 않음

넣지 않음: CAD · 좌측 카탈로그 상점 · DB · Production 기본 on · Three
